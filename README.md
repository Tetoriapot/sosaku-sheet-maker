# 創作シートメーカー

創作・うちよそ・TRPG向けの質問シートを、登録なしで作成・回答・共有できるWebアプリです。v0.4.0ではバックアップ・復元、公開内容の確認、回答の再開支援、保存シートの整理と12件の回答比較に対応しています。

GitHub Pages版は静的配信で、PNGと共有JSONファイルを使います。ローカルNode版ではSQLiteによる停止可能なURL共有も利用できます。実際のSupabaseへの接続はまだ行っていません。

## GitHub Pages

公開先：<https://tetoriapot.github.io/sosaku-sheet-maker/>

`pnpm build:pages` で `/sosaku-sheet-maker/` 向けのビルドを作ります。ハッシュ形式の画面URLを使用するため、回答・比較・Helpで再読み込みしても404になりません。別のパスへ配置する場合は `VITE_BASE_PATH` を指定します。

`.github/workflows/pages.yml` はmainへのpush時に、Node 24・pnpm 10で依存を固定インストールし、テスト・Pages用ビルド・デプロイを行います。リポジトリのSettings → PagesでSourceをGitHub Actionsに設定します。配信物は `dist/` のみです。利用者の回答や `.data/`、環境変数ファイルは公開しません。

PagesだけではNode APIを動かせないため、共有画面から公開項目を選んで共有ファイルを保存し、受け取る人はホームの「共有ファイルを開く」から取り込みます。回答ファイルは比較画面にも取り込めます。渡したファイルやPNGは取り消せません。ブラウザの画面URLだけでは個人の保存内容は共有されません。

ローカル版と公開版のブラウザ保存領域は別です。ローカルでバックアップを保存し、公開版で復元すると移行できます。共有停止用の管理情報は保存元のサイトでのみ復元します。

## v0.4.0の追加機能

- ホームから全シート・途中回答・完成した回答・タグ・再開位置をバックアップ。復元前に件数を確認し、同じIDは現在のデータを優先して追加します。表示モードは復元先の設定を使います。
- バックアップの上限は20MiB。未完成の質問・未回答の必須項目も保持し、不正な形式・重複ID・未対応バージョンは取り込み前に拒否します。復元の保存に失敗した場合、元データを保持します。
- 元のシートがない途中回答は、保存していたシートの内容からローカルの回答用シートも復元します。
- ローカル版では共有を停止する管理情報を任意で含められます。管理情報を含むバックアップは自分用として保管してください。異なるサイトへの復元では取り込みません。
- 共有前に回答者名・作者名・説明・補足コメントを選択し、プレビューを確認。除外した項目は共有データ本体からも削除します。本文に書いた情報は自動で消えません。
- 回答画面に前回の回答位置、最終保存時刻、未回答への移動、セクション目次。必須エラー時に一覧を表示し、入力欄へフォーカスします。
- 保存シートのタイトル・説明・作者・タグ検索、タグ絞り込み、更新日／タイトル順、アーカイブと復帰。整理情報は共有しません。
- 最大12件の回答比較、質問検索、表示する質問の選択、比較できない構成差の位置表示。

## 起動

Node.js 24以上とpnpmを使用します。標準のSQLite機能を使用するため、別のデータベースをインストールする必要はありません。

```sh
pnpm install
pnpm dev
```

表示されたローカルURLを開いてください。Viteと共有APIが同時に起動します。画面は `http://127.0.0.1:5174`、APIは8787番です。ブラウザの保存データはポートごとに異なるため、開発用のポートを5174に固定しています。使用中なら別ポートへ自動移動せず停止します。変更が必要な場合だけ `.env` の `DEV_PORT` を設定してください。

```sh
pnpm build
pnpm start
pnpm test
```

`pnpm start` はビルド済みの `dist/` と共有APIを同じサーバー（通常 `http://127.0.0.1:8787`）で配信します。`pnpm preview` も同じ動作です。各画面のURLへの直接アクセスにも対応しています。

## 回答比較

ホーム・回答結果の「回答を比較」、または `/compare` で使用します。

- このブラウザの回答、共有ファイル、書き出した回答JSONから2〜12件を選択。Node API版では同じサイトの回答結果URLも利用できます
- セクション・質問文・補足・回答形式・選択肢のラベルと順序・必須設定が同じ回答だけを比較。シート名や生成IDの違いは許容
- 複数選択は選択順に関係なく比較。「未回答」とスライダーの0を区別し、補足コメントの違いも表示
- 「違いのある項目だけ」で絞り込み。スマホでは比較表の中を横スクロール
- URL／JSONの取り込み内容は比較画面のメモリだけに保持し、サーバーへ送信しない。画面を離れると取り込み内容は消える
- ファイルは600KiB以下の回答JSONのみ。既存シートや回答を上書きするインポート機能ではない

## 今回の修正

- 質問追加の保存失敗時にモーダルを閉じず、入力と選択を保持
- 「もう一度回答」で途中の回答を消す前に確認
- 空白・改行のみの必須回答を未回答として検出
- 質問文・回答形式・選択肢の意味が変わった際、古い回答を別の意味で流用しない
- 別タブの保存変更を反映し、書き込み直前に最新の保存内容を読む。複数タブで同じ質問を同時編集する共同編集機能ではない
- 読めない保存データを空データで上書きせず、保存を停止して通知
- カスタム色が明るすぎる／暗すぎる場合、シートとPNGの見出し色を読みやすく調整
- 共有データ読み込みに15秒のタイムアウトを適用し、保存失敗通知が成功通知で消えるケースを修正

## URL共有

- 編集画面・ホーム・シート閲覧画面から「シートを共有」→「共有URLを作成」で回答用URLを作成します。
- 回答完了後の「回答結果をURLで共有」で閲覧用URLを作成します。入力途中の回答は送信されません。
- URLは作成時点の内容を固定します。元の編集・削除や、受け取った人のコピーは公開済みの内容に影響しません。
- ホームの「共有リンク」から共有を停止できます。回答結果と元の質問シートは別々に停止します。
- URLを知っている人が閲覧できます。公開一覧・検索APIはありません。匿名のランダムIDと256bitの管理用トークンを使い、ログインは不要です。
- 管理用トークンは作成したブラウザにだけ保存します。共有URL・APIの閲覧応答・回答JSONには含めません。サーバーにはハッシュだけを保存します。
- 通信失敗時に再試行しても同じIDを使用します。共有停止済みのIDを遅れた通信で復活させることはできません。
- 読み込み中、存在しないURL、通信エラー、再試行、クリップボードが使えない場合の手動コピーに対応しています。

ローカルの `127.0.0.1` URLはこのPCの別ブラウザで動作確認できます。インターネット越しに共有するには、NodeサーバーをHTTPSで公開してください。静的ファイルの配置だけでは共有APIは動きません。

### SQLiteの保存先

標準では `.data/shares.sqlite` に保存します。サーバーを再起動しても残ります。本番でSQLiteを使う場合はこのディレクトリを永続化し、稼働中のバックアップにはSQLiteのバックアップ機能を使ってください。自動有効期限は設けていません。共有停止時には公開データ本文を削除し、再作成を防ぐためのID・ハッシュ・日時だけを残します。

### Supabaseへの接続

1. SupabaseプロジェクトのSQL Editorで `supabase/migrations/202610020001_shares.sql` を一度実行します。
2. `.env.example` を `.env` にコピーし、`SHARE_STORAGE=supabase`、`SUPABASE_URL`、`SUPABASE_SECRET_KEY` を設定します。
3. `SUPABASE_SECRET_KEY` にはサーバー用の `sb_secret_*` または従来の `service_role` キーを設定します。**`VITE_` を付けず、ブラウザに配信しないでください。**
4. 開発サーバーを再起動するか、`pnpm build` → `pnpm start` で起動します。

同じAPIを通してSupabaseへ保存します。切り替え前にSQLiteで作成した共有データは自動移行されません。既存URLを維持する場合は、公開前にデータ移行を行う必要があります。

テーブルはRLSを有効にして `anon`／`authenticated` の直接アクセス権を取り除き、Node APIだけがサーバー用キーでアクセスします。キーとアクセス制御は[SupabaseのAPIキー](https://supabase.com/docs/guides/getting-started/api-keys)と[Data APIの保護](https://supabase.com/docs/guides/api/securing-your-api)の仕様に合わせています。SupabaseアダプターのHTTP契約はテスト済みですが、実プロジェクトへの接続とSQL適用は未検証です。

### 公開先の設定

`.env` の `PUBLIC_ORIGIN` に画面のHTTPSオリジン、必要に応じて `API_HOST=0.0.0.0` を設定し、同じオリジンで画面と `/api/*` を配信します。共有リンクは画面を開いたオリジンから生成します。リバースプロキシ配下でも `PUBLIC_ORIGIN` を設定してください。別の許可済みオリジンが必要なら `ALLOWED_ORIGINS` にカンマ区切りで指定します。

APIはデータ形状・回答型・ID重複・必須回答を検証し、本文600KiB、質問300件、セクション40件まで受け付けます。標準の制限は接続元IPごとに書き込み30回／分、読み込み300回／分です。Node単一プロセス内の制限で、再起動でリセットされます。リバースプロキシ配下ではプロキシのIP単位になるため、公開時にはプロキシ側の接続元別制限も設定してください。

### ブラウザの保存

LocalStorageは端末・ブラウザごとです。ブラウザデータの消去やプライベートブラウジングの終了で消える場合があります。大切なデータはバックアップを保存してください。バックアップ・共有ファイル・回答JSONはそれぞれ用途が異なり、画面で案内する形式を使用します。

Node API版の共有停止情報もLocalStorageに保存します。管理情報を含むバックアップがあれば同じサイトで復元できます。相手が保存した画像やシートのコピーは共有停止後も残ります。

## ファイル

`src/data/templates/` にテンプレート、`src/data/questions/` に質問ライブラリを配置。UIは `pages/` と `components/`、共通色・サイズは `styles/variables.css`、シートのテーマは `shared/themes.ts`、各画面はCSS Modules、保存は `utils/storage.ts`、PNG生成は `utils/exportImage.ts` です。

`server/` にNode APIとSQLite／Supabaseアダプター、`shared/validation.ts` に両側で使用する入力検証、`src/utils/sharing.ts` に共有APIクライアント、`src/hooks/useSharedResource.ts` に公開データの取得処理を置いています。`.env` と `.data/` はGit管理対象外です。
